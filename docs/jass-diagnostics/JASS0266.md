## JASS0266: Explicit Conversion Exists

| Property       | Value                    |
|----------------|--------------------------|
| **ID**         | JASS0266                 |
| **Descriptor** | ExplicitConversionExists |
| **Category**   | Semantic                 |
| **Severity**   | Error                    |

### Cause

This diagnostic is triggered when an expression cannot be implicitly converted to the expected type, but an explicit conversion exists for the type pair. Two cases trigger it:

- A narrowing `real` → `integer` conversion, made explicit with the `R2I` native.
- A handle downcast from a base type to a derived type (for example `widget` → `unit`).

### Rule description

JASS only converts `integer` to `real` implicitly. The reverse conversion truncates the fractional part and must be made explicit with the `R2I` native, so that the loss of precision is visible in the code.

Handle types form an inheritance hierarchy (`unit` extends `widget` extends `agent` extends `handle`). A derived value is implicitly usable where its base type is expected (an upcast), but the reverse is not: assigning a `widget` to a `unit` is a downcast. JASS has no cast operator, so the downcast is performed by saving the value with `Save*Handle` and loading it back with the typed loader for the derived type.

### How to fix violations

For the `real` → `integer` case, wrap the expression in `R2I`, or change the target's type.

For a handle downcast, store the value with `Save*Handle` and read it back with `Load*Handle`, or change the target's type to the base type.

### Example

```jass
function MyFunction takes nothing returns nothing
    local integer i = 3.14
    //                ^^^^ JASS0266: Cannot implicitly convert type 'real' to 'integer'; an explicit conversion exists (use R2I)
endfunction
```

Fixed code:

```jass
function MyFunction takes nothing returns nothing
    local integer i = R2I(3.14)
endfunction
```

Handle downcast example:

```jass
function MyFunction takes widget w returns nothing
    local unit u = w
    //             ^ JASS0266: Cannot implicitly convert type 'widget' to 'unit'; an explicit conversion exists (are you missing a cast?)
endfunction
```

Fixed code, casting the `widget` to a `unit`:

```jass
function MyFunction takes widget w returns nothing
    local hashtable ht = InitHashtable()
    local unit u
    call SaveWidgetHandle(ht, 0, 0, w)
    set u = LoadUnitHandle(ht, 0, 0)
endfunction
```

### When to suppress warnings

This is a compiler error and cannot be suppressed. Narrowing conversions and downcasts must be explicit.
