## JCA2000: Handle Leak

| Property       | Value       |
|----------------|-------------|
| **ID**         | JCA2000     |
| **Descriptor** | HandleLeak  |
| **Category**   | CodeQuality |
| **Severity**   | Warning     |

### Cause

This diagnostic is triggered when a handle is created via a native function (such as `Location`, `CreateGroup`, `Rect`, etc.) but is never destroyed before losing reference to it.

### Rule description

In Warcraft 3, many handle types require explicit cleanup to avoid resource leaks. When a handle-creating function is called and the result is stored in a local variable, the handle must be destroyed before the function exits, the function must return the handle, or the handle must be stored in a global variable. Failure to do so leaks the handle, which accumulates over time and can degrade game performance or cause crashes.

This diagnostic covers all handle types with simple create/destroy patterns, including:
- Location / RemoveLocation
- CreateGroup / DestroyGroup
- CreateForce / DestroyForce
- Rect / RemoveRect
- CreateRegion / RemoveRegion
- Condition, Filter, And, Or / DestroyBoolExpr
- AddSpecialEffect, AddSpecialEffectTarget / DestroyEffect
- CreateImage / DestroyImage
- CreateUbersplat / DestroyUbersplat
- AddLightning, AddLightningEx / DestroyLightning
- CreateTextTag / DestroyTextTag

### How to fix violations

Call the appropriate destroy/remove function before the reference to the handle is lost:

### Example

```jass
function CreateLocation takes nothing returns nothing
    local location loc = Location(100.0, 200.0)
    //             ^^^ JCA2000: Location may leak; call RemoveLocation when done
endfunction
```

Fixed code:

```jass
function CreateLocation takes nothing returns nothing
    local location loc = Location(100.0, 200.0)
    // ... use loc ...
    call RemoveLocation(loc)
endfunction
```

### When to suppress warnings

This warning should not be suppressed.
