## JASS1013: Invalid Number

| Property       | Value         |
|----------------|---------------|
| **ID**         | JASS1013      |
| **Descriptor** | InvalidNumber |
| **Category**   | Syntax        |
| **Severity**   | Error         |

### Cause

This diagnostic is triggered when a numeric literal is malformed.

### Rule description

JASS supports several numeric literal formats:

**Decimal literals:**
- `0`, `123`, `255`

**Hexadecimal literals:**
- `0x` prefix: `0x1F`, `0XFF`
- `$` prefix: `$FF`
- Must have at least one hex digit after the prefix

**Octal literals:**
- Starts with `0` followed by digits: `010`, `077`
- Digits must be 0-7 only

**Real literals:**
- `1.`, `3.14`, `.5`
- A lone `.` without any digits is invalid

### How to fix violations

1. Ensure hex literals have at least one digit after the `0x` or `$` prefix
2. Ensure octal literals only use digits 0-7, or remove any leading zeroes to make it a decimal literal
3. Ensure a dot has at least one digit on either side for real literals

### Example

```jass
globals
    integer x = 0x
    //          ^^ JASS1013: Invalid number '0x'
endglobals
```

Fixed code:

```jass
globals
    integer x = 0xFF
endglobals
```

Lone dot example:

```jass
globals
    integer x = .
    //          ^ JASS1013: Invalid number '.'
endglobals
```

Fixed code:

```jass
globals
    real x = 0.
endglobals
```

### When to suppress warnings

This is a compiler error and cannot be suppressed. The literal must be corrected to have a valid format.
